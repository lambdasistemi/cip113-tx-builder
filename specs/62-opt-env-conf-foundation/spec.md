# Feature Specification: opt-env-conf Foundation

## User Story

As a `cip113-cli` operator, I want repeated CLI settings to be accepted from
CLI flags, `CIP113_*` environment variables, and a YAML config file, so that
real transaction workflows no longer require repeating the same deployment and
node arguments on every command.

## Scope

This ticket lays the parser foundation for epic #61. It adds the
`opt-env-conf` dependency, introduces shared setting builders, rewrites the
top-level parser/dispatch, and proves the migration on `sign` and `vault seal`.

## Functional Requirements

- FR1: The `cip113-cli` executable depends on `opt-env-conf`, and the dependency
  resolves under the repository's pinned Nix/Haskell package set before broader
  implementation proceeds.
- FR2: `Cardano.CIP113.CLI.Settings` exposes reusable setting builders for
  deployment loading, node connection, change address, token name, and policy id.
- FR3: The existing flag names remain unchanged: `--deployment`,
  `--socket-path`, `--network-magic`, `--change-address`, `--token-name`, and
  `--policy-id`.
- FR4: Each migrated setting is visible through CLI flag, `CIP113_*`
  environment variable, and YAML config key help generated by `opt-env-conf`.
- FR5: The top-level parser uses `opt-env-conf` command dispatch and config-file
  wiring instead of `optparse-applicative` `hsubparser`, `ProviderOptions`, and
  manual global-vs-command-local merging.
- FR6: `sign` and `vault seal` parse through the new settings stack and keep
  their existing runtime behavior.
- FR7: Node-only real transaction behavior for register, transfer, freeze, and
  seize is preserved. Offline, Blockfrost, and Kupo real transaction building
  remain out of scope.

## Non-Goals

- Convert `register`, `transfer`, `freeze`, or `seize` command-specific parsers.
- Delete duplicate parser helpers outside the helpers explicitly moved from
  `Register.hs` into `Settings.hs`.
- Change deployment, registry, transaction-building, or provider semantics.

## Success Criteria

- `nix build .#cip113-cli` resolves and builds with `opt-env-conf`.
- `cip113-cli --help` shows flag, env var, and config key information for the
  migrated settings/config wiring.
- `nix build .#e2e-tests` followed by the CI-shaped e2e invocation passes.
- fourmolu and hlint pass on touched Haskell source.
